# MarkLite 规划

## 1. 产品定位

MarkLite 是一个**轻量、离线优先的 Markdown 写作工具**。目标不是成为功能最多的 Markdown IDE，而是把最高频的一条路径做得可靠：

> 打开一个本地 `.md` 文件 → 专注写作 → 看一眼排版 → 导出 PDF / Word。

核心原则：

1. **文件优先**：内容始终是普通 Markdown 文件，不引入私有格式或账号体系。
2. **离线可用**：编辑、保存、预览不依赖网络；导出最多依赖本机已有的浏览器内核。
3. **少而稳**：优先保证数据安全、中文排版和导出质量，再扩展高级能力。
4. **轻量交付**：不捆绑 Chromium/Electron，不要求安装 Office，安装包与内存占用尽量小。

主要用户：需要写中文技术文档、报告、说明书的工程师、教师、学生和办公用户。

## 2. v0.1 已完成范围

- 直接的 Markdown 文本编辑，编辑 / 左右分栏 / 预览三种模式
- 打开、保存、另存为、拖放打开、启动参数打开文件
- 未保存修改确认、关闭前确认、原子保存
- UTF-8 / GB18030 读取，UTF-8 写出
- 中文系统字体按需回退
- 中英文界面切换（语言选择持久化）
- 外观跟随系统 / 浅色 / 深色；5 套主题色；设置持久化
- 多文件标签页：多选/拖入打开、路径去重、独立状态、关闭确认、退出时全部保存
- 菜单栏与 Phosphor 图标（文件 / 查看 / 导出 / 帮助）
- 分栏内容实时联动（滚动位置暂不同步）
- PDF 导出：A4，标题、表格、代码块、引用、任务清单、提示框、脚注、本地图片
- Word 导出：标题、表格、超链接、引用、代码块、脚注、本地图片嵌入
- 核心逻辑与 GUI 分离，可无界面运行导出测试

## 3. 技术方案与取舍

### 3.1 GUI：egui / eframe

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| **egui（当前）** | 单进程纯 Rust、依赖少、启动快、跨平台、无 Node 工具链 | 原生控件与排版能力有限，复杂富文本编辑需自行实现 |
| Tauri + Web 前端 | 预览/PDF 排版天然接近浏览器，生态成熟 | 需要前端构建链，平台 WebView 差异，安装包与调试链路更重 |
| Qt / Slint | 原生控件成熟 | 依赖与授权复杂，纯 Rust 集成成本高 |

当前选择 egui，符合“轻量、纯本地、单文件交付”的目标。若未来需要所见即所得或复杂编辑器能力，再评估编辑器内核，而不是直接换成重型框架。

### 3.2 PDF：本机 Chromium 内核打印

| 方案 | 结论 |
| --- | --- |
| **系统 Edge/Chrome 无头打印（当前）** | 打印质量高，中文/图片/分页由成熟引擎处理；Windows 自带 Edge，无需打包浏览器 |
| 内嵌 Chromium | 质量同样好，但安装包增加数百 MB，与“轻量”冲突 |
| Typst 作为 Rust 库 | 纯 Rust、PDF 质量高，但依赖与编译体积较大，Markdown 到 Typst 的映射仍需维护 |
| 手写 PDF 排版 | 可控但表格、分页、中文字体嵌入成本过高 |

后续可增加 **Typst 可选后端**：在缺少浏览器或需要完全离线时作为 fallback；不替换默认链路。

### 3.3 Word：docx-rs

直接生成 OOXML，不依赖 Office、LibreOffice 或 Pandoc。导出结果是可继续编辑的原生 Word 文档，而不是图片或 HTML 伪装。

当前采用直接格式与文本项目符号，后续再补 Word 原生编号、目录与样式。

### 3.4 数据安全

- 保存采用临时文件 + 原子替换，减少崩溃/断电导致文件半写入的风险。
- 所有内容在内存中编辑，未保存状态有明确提示；关闭、新建、打开前均会询问。
- 原始 HTML 在 PDF 中默认不执行，避免本地 HTML/脚本注入。
- 文件编码优先 UTF-8；打开兼容 GB18030，写出统一 UTF-8（后续可提供“按原编码保存”选项）。

## 4. 路线图

### v0.2 — 写作体验（最高优先级）

目标：让“每天写”更顺手，并进一步降低丢稿风险。

- [ ] 自动保存草稿 + 崩溃恢复（保存到应用数据目录，不直接覆盖源文件）
- [ ] 最近文件与会话恢复（重启后恢复打开的标签页）
- [ ] 标签拖拽排序、关闭其他/关闭左侧标签页
- [ ] 查找 / 替换
- [ ] 分栏滚动位置联动（可选开关）
- [ ] 文档大纲侧栏（按标题跳转）
- [ ] 编辑器字号、字体、行宽设置
- [ ] 导出期间后台执行，界面显示进度，不冻结窗口
- [ ] 更完整的键盘导航与无障碍标签；可扩展的语言包结构
- [ ] 文件被外部修改时的检测与提示

### v0.3 — 内容与导出增强

- [ ] Word 原生自动编号列表、真正的标题样式与目录字段
- [ ] Word 表格样式、分页控制、页眉页脚选项
- [ ] PDF/Word 导出模板（简洁、报告、书籍），支持自定义 CSS/字体
- [ ] 代码语法高亮（编辑器与预览）
- [ ] 图片拖入、剪贴板粘贴，自动复制到相对目录
- [ ] 数学公式：可选 KaTeX 离线渲染或 Typst 后端
- [ ] Mermaid 等图表：通过可选插件/外部工具渲染为图片
- [ ] 导出 HTML（可作为无浏览器环境的 PDF 备用路径）

### v0.4 — 平台交付

- [ ] Windows 安装包（Inno Setup 或 WiX）、便携版 zip
- [ ] `.md` 文件关联与“打开方式”注册
- [ ] Windows 代码签名（减少 SmartScreen 提示）
- [ ] macOS `.app` 打包、公证与图标
- [ ] Linux `.deb` / AppImage（含 Wayland 支持）

### v1.0 — 生态与自动化（探索）

- [ ] CLI：`mdlite convert --pdf/--docx file.md`，便于脚本与 CI 批量转换
- [ ] 轻量插件机制（导出模板、图片/公式渲染器）
- [ ] 自定义主题包
- [ ] 用户自行选择的 Git/WebDAV 同步（不内置云账号）

## 5. 其它建议（按优先级）

### P0：应该尽快做

1. **自动保存与恢复**：即使有未保存确认，崩溃或系统重启仍可能丢稿。自动草稿是最有价值的下一个功能。
2. **最近文件与会话恢复**：重启后恢复打开的标签页，减少反复打开文件目录的成本。
3. **导出模板/样式设置**：当前导出质量已可用，但不同场景（技术文档、报告、讲义）对字体、页边距、页眉页脚的需求不同。
4. **原生 Word 列表与目录**：提升导出文档在 Word 中的可维护性。
5. **Windows 安装包和文件关联**：这是“可用工具”与“可交付产品”的分界线。

### P1：明显提升竞争力

- 查找替换、文档大纲、代码高亮
- 图片粘贴与自动资源目录
- 后台导出与导出预设
- PDF 无浏览器 fallback（Typst 或导出 HTML 后手动打印）
- macOS/Linux 实机适配与安装包
- 自动化测试覆盖导出文件结构（docx XML / PDF 页数 / 文本内容）

### P2：有明确需求后再做

- 数学公式、Mermaid、PlantUML
- 插件系统与第三方主题
- 导出为 HTML / EPUB
- 版本历史与文件快照（本地）
- 多窗口、分屏对照、专注模式

### 暂不建议

- 内置账号、云同步、协同编辑：与“本地优先、轻量”定位冲突，且显著增加安全与运维成本。
- 捆绑完整 Chromium：违背轻量目标；优先使用系统浏览器。
- 过早设计复杂插件系统：在核心编辑/导出路径稳定前，插件 API 容易反复破坏。
- 所见即所得双内核：会引入两套状态与光标映射，复杂度高；先用可靠的文本编辑 + 预览满足需求。

## 6. 质量与验收

每次发布前至少检查：

- [ ] 新建、打开、编辑、保存、另存为、关闭、取消路径均无数据丢失
- [ ] 中文、英文、混合文本在编辑器、预览、PDF、Word 中无乱码/缺字
- [ ] 标题、段落、粗斜体、删除线、链接、列表、任务列表、引用、代码块、表格、脚注、提示框导出正确
- [ ] 本地图片在预览、PDF、Word 中位置与比例正确
- [ ] 无浏览器时 PDF 导出给出可理解的错误；Word 导出不受影响
- [ ] 中文 / English 界面文案完整，对话框、状态栏与错误提示无硬编码残留
- [ ] 多标签页：切换保留状态、重复文件去重、关闭单个/全部未保存流程
- [ ] 菜单与图标在浅色/深色、中英文下无错位或缺字
- [ ] 跟随系统主题在 Windows / macOS / Linux 上切换正确
- [ ] 5 套主题色在浅色/深色下的对比度与选中态清晰
- [ ] 设置重启后保持；配置损坏时回退到默认值
- [ ] 深色/浅色主题可读性正常
- [ ] Windows 10/11 实机验证安装、文件关联、DPI 缩放、中文输入法
- [ ] 大文件（如 1 MB Markdown）编辑与预览不明显卡顿
- [ ] `cargo test`、`cargo test --lib --no-default-features` 全部通过
- [ ] 发布包包含图标、版本信息与 License

## 7. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 用户机器没有 Edge/Chrome | PDF 导出不可用 | 明确提示；后续提供 Typst fallback / 导出 HTML |
| 浏览器无头行为随版本变化 | 导出失败或排版变化 | 多候选浏览器 + 新旧 headless 参数重试；保留导出 HTML 诊断文件选项 |
| Word 直接格式在复杂模板中不一致 | 样式偏差 | 后续改用 Word 内置样式与编号；增加 docx XML 快照测试 |
| egui 文本编辑能力有限 | 大文件/复杂编辑体验受限 | 使用预览虚拟化；必要时评估专用编辑器内核 |
| 中文编码源文件 | 打开乱码 | 已支持 GB18030；后续增加编码选择与原编码保存 |
| 跨平台打包与签名成本 | 发布受阻 | Windows 优先；macOS/Linux 分阶段补齐 |

## 8. 下一迭代建议（具体）

按两周一个迭代估算：

1. 自动草稿与恢复：应用数据目录、定时写入、启动时检测、恢复/丢弃选择。
2. 最近文件与会话恢复：持久化最近路径与打开的标签页，并保留每个标签的视图状态。
3. 导出进度与后台执行：避免 PDF 生成时界面冻结；补充分栏滚动同步。
4. 补充导出自动化测试：解压 docx 校验关键 XML，PDF 校验页数与文本。
5. 在 Windows 实机完成首轮验收，修复 DPI、输入法、文件对话框细节。

---

规划会随实际使用反馈调整；优先级判断标准是“是否减少丢稿风险、是否提升每天写作频率、是否让导出结果更可直接交付”。
